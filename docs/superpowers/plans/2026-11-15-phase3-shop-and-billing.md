# Phase 3: Token shop (Tebex), plans, checkout, billing, playit.gg tunnels

> For agentic workers: each task is built by one agent in its own git worktree on top of phases 1-2. Tasks run in parallel, so the shared interfaces below are binding — code against them exactly even if the other task's code isn't on your branch yet (stub/fake them in tests).

## Owner's requirements (verbatim intent)
- Shop with **Tebex Headless** (many payment methods). **One-time purchases of tokens**, no subscriptions at Tebex.
- Players spend tokens on servers priced like "500 tokens / month"; tokens are taken automatically each period. When they run out: **suspend immediately, show a countdown until deletion**; admin chooses the grace period (e.g. 7 days, 1 day, 0 = delete immediately).
- Admin creates **categories**, and **plans** inside them: price per period, RAM, storage, CPU, backups, databases, ports, etc. Plans auto-sort cheapest first.
- **Price multipliers** per location or per node (e.g. 1x home server, 1.5x pro server).
- **Billing periods** the admin defines (30 / 90 / 365 days ...), with a discount or surcharge per period.
- **Capacity limits** (e.g. max 500 GB storage, 20 GB RAM, 1500% CPU sold in total). If a checkout would exceed them: purchase button greyed out and red text "We can't provide new servers right now — we've hit our limit!".
- **Checkout**: choose an egg (from the plan's allowed eggs), the billing period, a server name, optional add-ons (e.g. +1 backup for N tokens; hidden when none are enabled), then a **confirmation** ("every 30 days: 2 GB RAM ..."), confirm → **smooth loading screen** → "Purchase complete — your server is installing" with buttons "Go to server" / "Dashboard".
- **playit.gg**: each node runs a playit agent; the panel **creates a playit tunnel automatically for every new server** and shows the playit address (e.g. `xyz.joinmc.link`) instead of `0.0.0.0:25565`; tunnels are deleted with the server. Optional custom subdomain (`name.monoforge.net`) is a later extra (playit Premium + DNS) — show the input at checkout only if the admin enabled subdomains; a blocklist of names the admin reserves.
- In-panel warnings (use phase 1 `NoticeService::notify`) and email (phase 2 mail) for low balance, renewal failure, countdown to deletion.

## Facts
- Tebex Headless API base: `https://headless.tebex.io/api/accounts/{publicToken}`. Create basket: `POST {base}/baskets` body `{complete_url, cancel_url, custom: {...}, complete_auto_redirect, ip_address}` → `data.ident`, `data.links.checkout`. Add package: `POST {base}/baskets/{basketIdent}/packages` body `{package_id, quantity}`. Fixed packages ("500 tokens") are created by the owner in the Tebex creator panel.
- Tebex webhooks: header `X-Signature` = `hex(HMAC-SHA256(key=webhook secret, data=hex(SHA256(raw body))))`; source IPs `18.209.80.3`, `54.87.231.232` (configurable list); validation event `type: "validation.webhook"` → respond 200 `{"id": "<same id>"}`. Events: `payment.completed`, `payment.refunded`, `payment.dispute.opened|won|lost|closed`, `payment.declined`. Payment subject: `transaction_id`, `status{id,description}` (1 Complete, 2 Refund, 3 Chargeback), `price_paid{amount,currency}`, `customer{email,...}`, `products[]{id,name,quantity,custom}`; basket `custom` is echoed (verify with a test webhook; also accept it under products[].custom). Tebex Test Mode exists (no sandbox).
- playit.gg API (used by the official playit agent, undocumented): `POST https://api.playit.gg/{path}` JSON, header `Authorization: Agent-Key <agent secret>`; responses wrap data (expect `{"status":"success","data":...}` / error shape — handle both defensively).
  - `/tunnels/create` body `{"name": str|null, "tunnel_type": "minecraft-java"|"minecraft-bedrock"|"terraria"|"valheim"|"rust"|"7days"|"unturned"|"starbound"|null, "port_type": "tcp"|"udp"|"both", "port_count": 1, "origin": {"type": "agent", "data": {"agent_id": "<uuid>", "local_ip": "127.0.0.1", "local_port": <port>}}, "enabled": true, "alloc": null, "firewall_id": null, "proxy_protocol": null}` → `{id}`.
  - `/tunnels/list` body `{"tunnel_id": null, "agent_id": null}` → tunnels with `alloc: {status:"allocated", data:{assigned_domain, port_start, ip_hostname, assigned_srv?}}` or `pending` (poll).
  - `/tunnels/delete` body `{"tunnel_id": "<uuid>"}`.
  Errors are enums like `RequiresPlayitPremium`, `AgentNotFound`, `InvalidPortCount`. Treat the API as unstable: wrap in one client class, never fail a purchase because playit failed — record the error, show the node address as fallback, retry from the scheduler.

**Services** (exact signatures):
- Task Q `Pterodactyl\Services\Billing\TokenWallet`:
  - `balance(User $user): int`
  - `credit(User $user, int $tokens, string $type, string $description, ?string $refType = null, ?string $refId = null, array $meta = []): TokenTransaction` (tokens > 0)
  - `debit(User $user, int $tokens, string $type, string $description, ?string $refType = null, ?string $refId = null, array $meta = [], bool $allowNegative = false): TokenTransaction` — locks the user row (`lockForUpdate`), throws `Pterodactyl\Exceptions\Billing\InsufficientTokensException` when the balance would go negative and `$allowNegative` is false.
  - Idempotency helper `hasTransaction(string $refType, string $refId, string $type): bool`.
- Task R `Pterodactyl\Services\Billing\PricingService`:
  - `quote(ShopPlan $plan, ShopPeriod $period, Node $node, array $addons): Quote` where `$addons` is `array<string key, int units>` and `Quote` (readonly class `Pterodactyl\Services\Billing\Quote`) has `int $basePerPeriod`, `float $multiplier`, `int $addonsPerPeriod`, `int $totalPerPeriod`, `int $periodDays`, `array $lines` (`[{label, tokens}]`), `array $resources` (final memory/disk/cpu/backups/databases/allocations incl. add-ons).
  - Formula: base = round(price_tokens × days/30); with period modifier `× (1 + price_modifier_percent/100)`; multiplier = node multiplier ?? location multiplier ?? 1.0; addons = Σ units × addon.price_tokens × days/30 × (1+modifier); total = ceil((base × multiplier) + addons). Always integers, never below 1.
  - `CapacityService::canProvision(array $resources): bool` and `remaining(): array` — sums resources of all servers with an `active|suspended` subscription (shop-sold servers only) against the limits; 0 limit = unlimited.
- Task T `Pterodactyl\Services\Billing\SubscriptionService`:
  - `start(Server $server, User $user, ?ShopPlan $plan, ShopPeriod $period, Quote $quote, array $addons): ServerSubscription` (next_renewal_at = now + period days; the first period is paid by the caller before this)
  - `renew(ServerSubscription $s): bool` (debit; on InsufficientTokens → `suspend`)
  - `suspend(ServerSubscription $s): void` (suspends the Pterodactyl server via the existing suspension action, sets delete_at = now + grace_days, notifies), `unsuspendIfPaid(ServerSubscription $s): bool`, `cancel(ServerSubscription $s)`, `deleteExpired(): int` (deletes servers whose delete_at passed, via the existing server deletion service; also deletes tunnels via Task V's `TunnelService::release(Server)` if the class exists).
- Task V `Pterodactyl\Services\Tunnels\TunnelService`: `provision(Server $server): ServerTunnel` (idempotent; dispatches/queues), `release(Server $server): void`, `displayAddress(Server $server): ?string` (playit address if active, else null). A `PlayitClient` class wraps the HTTP API.
- Task S checkout uses: `PricingService::quote`, `CapacityService::canProvision`, `TokenWallet::debit`, existing server creation (`Pterodactyl\Services\Servers\ServerCreationService` or the 2.0 equivalent action — find it) with deployment to a node from the plan's allowed nodes that has free allocations, then `SubscriptionService::start`, then `TunnelService::provision` (when the class exists; feature-detect).
